# Icon item ID tables and `check-icon-map`: decision report

Ticket: Icon item ID tables and `check-icon-map`. Spec: §11.9. Branch: `t3/icon-item-id-tables-check`. Audit: Claude seat only. Gemini and GPT: not run (out of quota). Pack layout doc: [docs/icon-packs.md](../../../../docs/icon-packs.md).

## Decisions

1. **Where the Gen 1-2 dex tables live.** Question: the ticket says Gen 1-2 species resolve "once their reference data is present", but `referenceData("gen1" | "gen2")` returns null and no ticket ships it yet. Options: wait for that reference data, or ship icon-local dex tables. Choice: ship the tables in `icon-maps.json` and read them in `DEFAULT_MAPS.dex`, so Gen 1-2 species resolve now. Gen 1 maps the cartridge's internal order to the dex (151 entries, with gaps), and Gen 2 is the identity on 1-251. Both come from PokeAPI `pokemon_game_indices`, and the generator fails if the games of one generation disagree. Made by: implementer.

2. **Source of the item tables.** Choice: PokeAPI `item_game_indices` at a pinned `PokeAPI/pokeapi` commit (`cd5f6c62`, 2026-11-20), one generation per art version (1: red-blue, red-green-japan, yellow; 2: gold, silver, crystal; 3: the three Gen 3 art versions). Generated by `bun run generate:icon-maps`, and a rerun gives a byte-identical file. Made by: implementer.

3. **Gen 3 item IDs.** Choice: only IDs that have a real name in the checked-in `gen3-en.json` (not the `????????` filler) are mapped, so PokeAPI indices with no game item behind them never leak in. All real names but seven agree with PokeAPI's name for the same index; I checked the seven by hand (renames such as `STICK` to Leek, `X DEFEND` to X Defense, and `OAK'S PARCEL` to Parcel). Index 261 lists two PokeAPI items, so the game name `ITEMFINDER` picks Dowsing Machine through a one-entry `RENAMED` alias. Name matching is the fallback for a name with no index, as the spec says. Made by: implementer.

4. **Gen 1-2 ambiguity.** Choice: an index that PokeAPI gives to two items (Gen 2 indices 116 and 221) is left out, since Gen 1-2 ship no item names to choose by. Those two IDs answer 404. Made by: implementer.

5. **Only slugs with art.** Question: should a table list every item PokeAPI knows or only items with art. Choice: only slugs with a file under `sprites/items/` at the pinned sprites SHA, listed through GitHub's tree API because jsDelivr refuses to list the repo. This keeps the tables equal to what resolves, and the acceptance wording "items PokeAPI has art for" follows. Result: 130 items (Gen 1), 203 (Gen 2), 308 (Gen 3). Made by: implementer.

6. **One table for all three Gen 3 art versions.** PokeAPI keeps one generation-III index, and the reference names agree across Ruby, Emerald and FireRed, so the three tables are equal. The type keeps one table per art version as the spec says, and a test pins that they are equal. Made by: implementer.

7. **`check-icon-map`.** Choice: `scripts/check-icon-map.ts`, run by `bun run check-icon-map [mirrorUrl]`. `server/src/icons/coverage.ts` lists every upstream path the maps can reach through `planIcon` over one official game per art version (5058 paths). It sends a HEAD request for each. It is not part of `bun test` or any workflow, so CI stays offline, and a job opts in by running the script. Tests cover the path list offline. Made by: implementer.

8. **jsDelivr 403s.** Finding: a full run showed 29, then 60, then 2 failures, all HTTP 403, and different files each time. A one-byte GET succeeds for most of them, so jsDelivr throttles or flakes a burst of HEADs. The script retries, falls back to a GET for a non-404 refusal, and rechecks failures one at a time. Two paths still fail every time: `pokemon/versions/generation-iii/firered-leafgreen/shiny/212.png` and `.../generation-iii/icons/149.png`. jsDelivr answers 403 "Package size exceeded the configured limit of 50 MB". Both files exist on `raw.githubusercontent.com` and in the repo tree, and they return 403 at `@master` as well, so pinning a newer SHA does not help. The spec's "pin a newer SHA where it passes" has no passing SHA, so this stays open. Follow-up ticket surfaced for the master. Made by: implementer.

## Audit verdict

APPROVE at round 2. Claude seat 8, Gemini and GPT: not run (out of quota). One minor problem declined.

- Round 1: DISAPPROVE 7, one blocking and one minor.
- Fixed (minor): `byName` indexed a slug and its English name under the same key, so the name fallback saw two copies of one slug and gave up. It now dedupes, and a test covers it. The generated file is unchanged.
- Rebutted (blocking): the two persistent jsDelivr 403s. The mapping is right, a newer SHA does not pass, and the fix lies in the `/icons` service or the source choice (decision 8). The seat dropped it at round 2.

## Minor problems declined

- Declined: `check-icon-map` still exits 1 on the two jsDelivr 403s, and the default source serves those two Gen 3 icons as 403 at runtime. The seat agreed the follow-up ticket is the right handling. A fix here would change the `/icons` route's source design, which belongs to its own ticket.

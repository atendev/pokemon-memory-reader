## Synthesis / open gaps
- Concrete path: (1) rebuild bun from oven-sh/bun@bun-v1.4.2 with modified vendor/WebKit (`bun sync-webkit-source`, then scripts/build.ts with webkit=local) or modified tinycc (edit the github-archive source / patch); (2) rebuild our app: `bun build --compile --compile-executable-path ./modified-bun ...` or Bun.build `compile.executablePath`. Needs our app source/bundle input (we ship source or an equivalent). Cross targets require a modified bun built per target (or a target bun supplied by path); Windows local WebKit requires a Windows host (config.ts:1081-1084); no windows-arm64-lto prebuilt.
- Gaps: (a) not verified whether `build:local` (debug profile) vs release profile + `--webkit=local` yields a release-equivalent bun; (b) no extraction tool for payload re-attach found (only rebuild path); (c) JSC bytecode compatibility across JSC builds not verified (matters only if --bytecode used); (d) archive contents not downloaded/inspected (400MB+), static-lib claim is from source; (e) tinycc has no separate relink doc beyond LICENSE.md table row; tinycc modification means editing oven-sh/tinycc at the pinned commit and rebuilding bun; (f) macOS: rewritten/relinked binary needs codesign (CONFIG_CODESIGN refers to tinycc; Bun macho signing not checked).

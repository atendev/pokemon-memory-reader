# 024 Hack species data (CFRU vs vanilla)

Status key: confirmed / inferred / unknown. Sources: primary repo files.

Pinned commits: CFRU `b637a27898` (master), DPE (Skeli789/Dynamic-Pokemon-Expansion) `cdfc053a56`, pokefirered `ce6406d8c2` (master; struct renamed `SpeciesInfo`) and `b2c74cae84` (2022, still `BaseStats`), pokeemerald `731ad5bfd6`.
Links below use `master` unless a sha is given; line numbers are from those commits.

## 1. Vanilla Gen 3 BaseStats

- **Layout (confirmed).** `genderRatio` u8 at 0x10, `growthRate` u8 at 0x13, `abilities[2]` u8 at 0x16 and 0x17, `safariZoneFleeRate` 0x18, `bodyColor:7`/`noFlip:1` at 0x19. Source: [pokefirered include/pokemon.h @b2c74cae84 L201-L231](https://github.com/pret/pokefirered/blob/b2c74cae8456cfa10a27a3a2d4b97971fd964b6d/include/pokemon.h#L201-L231) (`genderRatio` L221, `growthRate` L224, `abilities` L227). Current master has the same offsets under the name `struct SpeciesInfo` ([include/pokemon.h L208-L233](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/include/pokemon.h#L208)).
- **Size 0x1C (inferred).** The decomp struct text ends at 0x1A (bodyColor/noFlip at 0x19), so the 0x1C stride is not written anywhere in the struct. CFRU's version (see 2) ends with `u8 hiddenAbility` at 0x1A, giving 0x1B bytes, which the compiler rounds to 0x1C because the struct has u16 members (2-byte alignment). 0x1C is also the stride the task expected. No `sizeof(struct BaseStats)` appears in pokefirered, CFRU or DPE (code search). Check on a real ROM: bytes at `gBaseStats + 0x1C` must start Ivysaur's stats (60,62,63,60,80,80 for HP, Atk, Def, Spe, SpA, SpD).
- **Header pointer, FireRed (confirmed).** `0x080001BC`. `struct GFRomHeader` in [pokefirered src/rom_header_gf.c L10-L90](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/rom_header_gf.c#L10) puts `speciesInfo` 0xEC bytes into the header; with the header at 0x100, `monSpeciesNames` lands at 0x144 and `speciesInfo` at 0x1BC. DPE's [`repointall` L5-L6](https://github.com/Skeli789/Dynamic-Pokemon-Expansion/blob/master/repointall#L6) lists `gSpeciesNames 08000144` and `gBaseStats 080001BC`, and CFRU's [`include/new/rom_locs.h` L13](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/new/rom_locs.h#L13) reads it as `#define gBaseStats ((struct BaseStats*) *((u32*) 0x80001BC))`.
- **Header pointer, Emerald (inferred).** [pokeemerald src/rom_header_gf.c L72](https://github.com/pret/pokeemerald/blob/731ad5bfd6/src/rom_header_gf.c#L72) has `speciesInfo` at the same field offset (0xEC) with `monSpeciesNames` at 0x44, so the pointer is `header_base + 0xEC`. The header base address (0x100) comes from [the ROM layout](https://github.com/pret/pokeemerald/blob/731ad5bfd6/ld_script.ld#L50) (`rom_header.o` then `rom_header_gf.o`), but the source does not state it. Treat `0x080001BC` for Emerald as unverified; read it from a real Emerald ROM.

## 2. CFRU `struct BaseStats`

- **Same offsets, one byte added (confirmed).** [CFRU include/pokemon.h L510-L542](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/pokemon.h#L510): every vanilla offset is unchanged (`genderRatio` 0x10 L530, `growthRate` 0x13 L533), the two abilities are now named `ability1` 0x16 L536 and `ability2` 0x17 L537, and `/* 0x1A */ u8 hiddenAbility;` is added at L541. DPE's [include/base_stats.h](https://github.com/Skeli789/Dynamic-Pokemon-Expansion/blob/master/include/base_stats.h) has the identical struct, and DPE's [src/Base_Stats.c L10](https://github.com/Skeli789/Dynamic-Pokemon-Expansion/blob/master/src/Base_Stats.c#L10) is the `gBaseStats[]` table that gets inserted.
- **Hidden ability byte (confirmed).** Offset 0x1A, a u8 ability ID, `ABILITY_NONE` (0) when absent. It sits in what is padding in the vanilla 0x1C-byte entry (see the size note in 1), so vanilla-layout readers that only read 0x16/0x17 still work.
- **Size (inferred).** 0x1B bytes of fields, rounded to 0x1C by u16 alignment, same stride as vanilla. A hack inserting through DPE gets the stride from the compiler, so it should be 0x1C. Not stated in source; verify on a hack ROM by checking entry 2 begins at table + 0x1C.
- **No widened fields (confirmed).** `ability1`, `ability2` and `hiddenAbility` are all u8. [CFRU include/constants/abilities.h L264](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/constants/abilities.h#L264): `#define ABILITIES_COUNT (ABILITY_PASTELVEIL + 1)` with `ABILITY_PASTELVEIL 0xFE` (L259), so CFRU tops out at 255 abilities (IDs 0-254). Vanilla has 78 (IDs up to 0x4D).
- **Radical Red ability count (unknown).** Radical Red's source is not published (it is distributed as a patch built on CFRU), so there is no primary source for its ability table or `BaseStats` layout. Only the CFRU engine limit (u8, under 255) is confirmed; a custom fork could differ.

## 3. How a mon records its ability slot

- **Vanilla (confirmed).** One bit in the misc substructure (substruct 3, the one with pokerus/met data/IVs/ribbons): the IV word at 0x04 is `hpIV:5 attackIV:5 defenseIV:5 speedIV:5 spAttackIV:5 spDefenseIV:5 isEgg:1 abilityNum:1`, so `abilityNum` is bit 31 of that u32 (L56-L57 of [pokefirered include/pokemon.h](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/include/pokemon.h#L56)). It is written at creation as `personality & 1` only when `abilities[1]` is nonzero ([src/pokemon.c L1855-L1859](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/pokemon.c#L1855)); the ability is `abilities[abilityNum]`.
- **CFRU (confirmed).** The same bit position (bit 31 of the IV word in substruct 3) is renamed `hiddenAbility:1` ([CFRU include/pokemon.h L248-L249](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/pokemon.h#L248), also L359-L360 for the party `Pokemon` copy); the old name `altAbility:1` survives only in `UnknownPokemonStruct` L424 and `BattlePokemon` L448. [CFRU src/build_pokemon.c L4545-L4558](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/src/build_pokemon.c#L4545) `GetMonAbility`: if the bit is set and `gBaseStats[species].hiddenAbility != ABILITY_NONE` the hidden ability is used; otherwise slot 1 is chosen when `personality & 1 == 0` or `ability2 == NONE`, else slot 2. So the stored bit no longer picks between slots 1 and 2; personality parity does, and the bit only means "hidden". `GetAbilityBySpecies(species, altAbility)` is still declared at L815.
- **Caveat (inferred).** Substruct order in the 48-byte encrypted block depends on `personality % 24` and the block is XOR-encrypted with `personality ^ otId`, same as vanilla. Nothing in CFRU's struct changes that. CFRU's `PokemonSubstruct3` L229-L270 has the same 12-byte shape as vanilla (the vanilla 4-bit `pokeBall` field at 0x02-0x03 is replaced by `gigantamax:1` plus `blank:3`; not checked against the vanilla struct line).

## 4. National Dex number

- **Vanilla (confirmed).** `static const u16 sSpeciesToNationalPokedexNum[NUM_SPECIES - 1]` in [pokefirered src/pokemon.c L519](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/pokemon.c#L519), read by `SpeciesToNationalPokedexNum` as `[species - 1]` with 0 returned for species 0 ([L5210-L5216](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/pokemon.c#L5210)). Element type u16. Vanilla `NUM_SPECIES` is `SPECIES_EGG` = 412 ([constants/species.h L423](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/include/constants/species.h#L423)), so 411 entries. No GF header slot points to it, and its BPRE address is not in CFRU's `BPRE.ld`. Unknown: its vanilla ROM address (read the literal pool at 0x0804323C, see below).
- **CFRU/DPE (confirmed that it is repointed, not that it is in the header).** CFRU's own `repoints`/`repointall` do not mention it. The table belongs to DPE (CFRU's README points to DPE as the Pokemon expansion: [README L77](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/README.md)). DPE [`repointall` L26](https://github.com/Skeli789/Dynamic-Pokemon-Expansion/blob/master/repointall#L26): `gSpeciesToNationalPokedexNum 0804323C`. The `repointall` header (L3-L4) says it reads the pointer stored at the given ROM address and replaces every pointer to that old value, so `0x0804323C` is a literal-pool word inside vanilla `SpeciesToNationalPokedexNum`, not a header slot. A ROM reader finds the new table by reading the u32 at `0x0804323C` (valid for BPRE 1.0 only).
- **Element type and form mapping (confirmed).** `const u16 gSpeciesToNationalPokedexNum[NUM_SPECIES - 1]`, designated initialisers `[SPECIES_X - 1] = NATIONAL_DEX_X` ([DPE src/Species_To_Pokdex_Table.c L4](https://github.com/Skeli789/Dynamic-Pokemon-Expansion/blob/master/src/Species_To_Pokdex_Table.c#L4)). Internal IDs are not dex numbers: Gen 1-2 are 1-251 (0xFB Celebi), Hoenn starts at 0x115 (Treecko), Chimecho is 0x19B, Egg 0x19C, `UNOWN_B` 0x19D, then Gen 4+ and forms ([CFRU include/constants/species.h](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/constants/species.h) L256-L422, L854, L1007). Forms are separate species IDs mapped to the base dex number, for example `[SPECIES_VENUSAUR_MEGA - 1] = NATIONAL_DEX_VENUSAUR` (table L874), `SPECIES_RATTATA_A` -> `NATIONAL_DEX_RATTATA` (L1033), `SPECIES_UNOWN_B` -> `NATIONAL_DEX_UNOWN` (L418). No separate form table.
- **Table length (inferred).** `NUM_SPECIES - 1` entries, 0x50D = 1293 (see 6), 2 bytes each. A hack that did not link DPE (or modified it) could differ; check the pointer at 0x0804323C and the species count.

## 5. Experience and growth

- **Six growth rates unchanged (confirmed).** CFRU's enum is the vanilla order `MEDIUM_FAST, ERRATIC, FLUCTUATING, MEDIUM_SLOW, FAST, SLOW` ([include/pokemon.h L558-L566](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/pokemon.h#L558)) and [src/Tables/experience_tables.c L1269-L1409](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/src/Tables/experience_tables.c#L1269) has the same six rows in that order. Row 0 starts `0, 1, 8, 27, 64...` (n^3), as vanilla.
- **The table is widened (confirmed).** CFRU defines `const u32 gExperienceTables[][255 + 1]` ([experience_tables.c L1267](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/src/Tables/experience_tables.c#L1267), also [rom_locs.h L22](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/new/rom_locs.h#L22)). Vanilla is `[][MAX_LEVEL + 1]` with `MAX_LEVEL` 100, so rows are 101 u32 (0x194 bytes), not 256 (0x400 bytes). The row stride is 0x400 in CFRU; a reader must not hard-code 101 columns on a hack.
- **Level cap (confirmed for default, hack-configurable).** CFRU keeps `#define MAX_LEVEL 100` ([src/config.h L139](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/src/config.h#L139), "Also change this in asm_defines.asm") and `MAX_MON_LEVEL 100` (pokemon.h L140). The 256 columns exist so a hack can raise it, up to 255. A hack author could do so; whether a given hack does is unknown.
- **Where the table pointer lives (confirmed).** It is not in the GF header. CFRU's [`repoints` L25-L42](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/repoints#L25) lists 18 literal-pool locations (for example `gExperienceTables 0802FFB8`, `0803E828`, `0803E894`) that are rewritten to the new table. [BPRE.ld L465](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/BPRE.ld#L465) puts vanilla `GetLevelFromBoxMonExp` at `0x0803E830`, which sits between two of those pool locations, so the vanilla function's own pool is the one repointed. `repoints` differs from `repointall` in that it rewrites exactly the listed word, not every copy of the old pointer (inferred from the file's header comments).
- **Boxed mon level (inferred, high confidence).** A boxed mon stores `experience` (u32, substruct 0) but no level. CFRU calls the vanilla ROM function (`GetLevelFromBoxMonExp`, [pokemon.h L681](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/pokemon.h#L681)), so level = largest L with `gExperienceTables[growthRate][L] <= exp`, using the hack's `growthRate` (BaseStats 0x13) and the repointed table (stride 0x400, cap at `MAX_LEVEL`). CFRU's own `SetMonExpWithMaxLevelCheck` clamps exp to `gExperienceTables[growthRate][MAX_LEVEL]` ([build_pokemon.c L4561-L4568](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/src/build_pokemon.c#L4561)).
- **Gender (confirmed that CFRU uses the vanilla routine).** [pokemon.h L692](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/pokemon.h#L692) declares `GetGenderFromSpeciesAndPersonality` as a ROM `long_call` and [BPRE.ld L472](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/BPRE.ld#L472) gives its vanilla address `0x0803F78C`. So gender is still decided by `genderRatio` (0x10) against the low byte of personality; only the table location changes.

## 6. Species table length and base stats pointer

- **Highest species ID (confirmed).** `SPECIES_URSHIFU_RAPID_GIGA 0x50D` and `#define NUM_SPECIES (SPECIES_URSHIFU_RAPID_GIGA + 1)`, so `NUM_SPECIES` = 0x50E = 1294 ([CFRU include/constants/species.h L1295 and the last define](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/include/constants/species.h#L1295)); DPE has the same `NUM_SPECIES` ([DPE include/species.h L1265](https://github.com/Skeli789/Dynamic-Pokemon-Expansion/blob/master/include/species.h#L1265), line number is that file's own). Vanilla FireRed is 412. Species IDs are u16. Hacks built on CFRU can add or trim entries, so read the count from the hack, not from this constant (unknown per hack).
- **Pointer at 0x080001BC repointed (confirmed for DPE-based builds; not in CFRU's own lists).** DPE [`repointall` L6](https://github.com/Skeli789/Dynamic-Pokemon-Expansion/blob/master/repointall#L6) `gBaseStats 080001BC`; this also appears in the 010 research asset. CFRU's own `repoints` and `repointall` (all revisions checked: `d8026d6bf`, `cfafcc896`, `083d2fc77`, `b6ceb9e71`, master) contain no `gBaseStats` line and no `gSpeciesToNationalPokedexNum` line. The 010 asset cited the line as CFRU/DPE; it lives in DPE only. CFRU reads the table through the header at run time (`rom_locs.h` L13), which only works because DPE repoints it. Open: whether a given CFRU hack applied DPE (or equivalent). In practice CFRU hacks carry the base stats table through header 0x080001BC; this is an inference, not proved per hack.
- **Name-table and other cross-checks (confirmed).** `gAbilityNames 080001C0` is in CFRU's own [`repointall` L6](https://github.com/Skeli789/Complete-Fire-Red-Upgrade/blob/master/repointall#L6), so ability names are readable from the header too.

## Practical read recipe for a hack profile (inferred from the above)

1. `base = u32 @ 0x080001BC`; entry = `base + species * 0x1C` (species indexes the table directly, no `-1`; entry 0 is all zero).
2. `genderRatio = entry[0x10]`, `growthRate = entry[0x13]`, abilities `entry[0x16]`, `entry[0x17]`, hidden `entry[0x1A]` (hack only; on vanilla it is padding, treat as 0).
3. Ability: if the misc-substructure bit (bit 31 of the IV word at +0x04) is set and `entry[0x1A] != 0` use the hidden one; else `personality & 1 == 0 || ability2 == 0 ? ability1 : ability2`. For vanilla-layout games use the stored bit as the slot.
4. National Dex: `u16 table[species - 1]`, table pointer from the u32 at `0x0804323C` on BPRE 1.0 hacks that include DPE; fall back to `null` when that word does not point into ROM.
5. Level of a boxed mon: needs `gExperienceTables`, whose pointer is only in literal pools (for example the u32 at `0x0803E894` on BPRE 1.0 CFRU builds, inferred from L30 of `repoints`; the pool word matching `GetLevelFromBoxMonExp` was not verified). Row stride 0x400 on CFRU, 0x194 on vanilla; cap 100 unless the hack changed it.

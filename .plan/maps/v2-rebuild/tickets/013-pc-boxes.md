# PC box reading

## Question

Do PC boxes belong in the first release, and how does each generation expose them?

`boxes` is reserved in the route namespace by [API v2 contract](./006-api-contract.md). Decide the scope per generation, the resource shape (box names, wallpapers, slot order, the Pokemon fields stored in a box versus the party), how large reads stay cheap, and whether the viewer gets a Boxes screen.

## Answer

PC boxes ship in v2.0 for Gen 1, Gen 2 and Gen 3 (including CFRU where the profile supports it). `boxes` is one whole-resource stream topic with a per-box snapshot route, and boxes are read only on demand. The viewer gets a fifth screen, Boxes.

- **Scope.** All three generations. Gen 3 reads `PokemonStorage` from RAM (not save sectors) in one contiguous read, about 33 KB, and `currentBox` is its first byte. The profile gives the base address as a static `gPokemonStorage` (Ruby, Sapphire) or through the `gPokemonStoragePtr` pointer entry (Emerald, FireRed, per [Game profile source](./005-game-profile-source.md)): 14 boxes of 30 slots, names and wallpapers. Gen 1 (12 boxes of 20) and Gen 2 (14 boxes of 20) keep only the current box in WRAM. The other boxes sit in cartridge SRAM and are only as fresh as the last in-game save or box switch. `.describe()` and the docs say so. The current box always comes from WRAM and replaces its SRAM copy. If the adapter exposes no SRAM domain, only the current box is readable.
- **Resource.** `boxes = { currentBox: number | null, boxes: Box[] }`, with `Box = { index, name, wallpaper, readable, corruptSlots, slots }`. `index` and `currentBox` are 0-based. For a readable box, `slots` has a fixed length (20 for Gen 1-2, 30 for Gen 3) in game slot order, with `null` for an empty slot so slot indices hold. Only an unreadable box breaks that rule: it has `readable: false`, `slots: []`, `corruptSlots: []`, and keeps its `name` and `wallpaper` where they are known (otherwise `null`). That includes every box of a Gen 3 storage block that fails to read, in which case `currentBox` is `null`. `name` is the decoded text (up to 8 characters in Gen 3), and `wallpaper` is the game's wallpaper index as a number. Gen 1 has no box names, and Gen 2 has names but no wallpapers. Verify both, and the Gen 2 name length and charmap, against the pret disassemblies before implementing. Gen 1 `name` and `wallpaper` are `null`, and Gen 2 `wallpaper` is `null`.
- **Corrupt slots.** A Gen 3 slot that fails its checksum, and a Gen 3 bad egg, becomes `null` and its index goes in `corruptSlots` (never omitted, `[]` by default), so a tracker can tell empty from corrupt. Gen 1-2 have no checksums: `corruptSlots` is always `[]`, and a slot with an invalid species is `null` and not listed. Both cases log one warning per box index and slot until the game changes. Gen 1-2 slots are decoded by position, ignoring the count byte and the species terminator list. Eggs otherwise follow the party schema's egg marker. A boxed Gen 3 egg's `level` is computed from exp like any other, so clients check the egg marker before showing it.
- **Box Pokémon.** The same `Pokemon` schema as the party. Fields a box doesn't store are `null`: `hp`, `maxHp`, `stats` and `status` in Gen 2 and Gen 3, and `stats` and `maxHp` in Gen 1 (a Gen 1 box mon stores HP and status; a Gen 2 box mon stores neither). Gen 3 `level` is computed from exp and the species growth rate (a small table in reference data). Gen 1-2 use the stored box level. No stats are computed in v2.0. Adding them later is additive. `.describe()` lists the null fields. The party and `battle` Pokémon schemas declare these fields nullable from the start (`hp`, `maxHp`, `stats`, `status`). v2 is unreleased, so this breaks nothing.
- **Routes and stream.** `GET /api/v2/boxes` returns the whole resource. `GET /api/v2/boxes/:n` returns one `Box` and is not a stream topic. An out-of-range or non-integer `:n` returns `404 { error: { code: "not_found", message }, status }`, and `not_found` joins 006's error codes (additive). A valid `:n` whose box is unreadable returns `200` with `readable: false`. The 503 checks (`disconnected`, `no_game`, `unsupported`) run before `:n` validation. The `boxes` SSE topic carries the whole resource in every event, as in 006, and the server pushes it only when a client subscribed to it. With no game, a disconnected adapter or an unsupported profile, the topic stays silent, because 006's stream never errors.
- **Support flag.** `status.game.features: { boxes: boolean } | null` is added to 006's status (`null` while no game is loaded, an object that may gain more booleans later). It is true when the profile's data format supports boxes. Hack profiles with an unverified storage layout set it false, and `GET /boxes` and `GET /boxes/:n` return `503 unsupported`. The same 503 applies when the adapter can't perform the resource's main read at all, which is the Gen 3 mGBA GDB case below if that read is not chunked, while the flag stays true, because the flag is per profile. A missing SRAM domain is not that case: it only makes the affected Gen 1-2 boxes `readable: false`, and the resource still returns `200` with the current box. Per-box readability stays on `Box.readable`. The flag is per profile, not per adapter: it promises data from at least the current box. On an adapter with no SRAM access (RetroArch is unverified), Gen 1-2 non-current boxes are `readable: false` while the flag stays true. That is accepted for v2.0, and the Boxes screen explains it in its note.
- **Read cost.** Boxes are read only while a client subscribes to the `boxes` topic or a snapshot is requested. They are not part of the always-on read cycle that serves `status`, `player`, `party`, `bag` and `battle`. Gen 3 uses one contiguous read, and Gen 1-2 use one read per box. Gen 1-2 SRAM boxes are trusted as stored: the program doesn't verify the save checksum. The program hashes the raw bytes of every region read (the WRAM current box plus each SRAM box) and emits an event only when a hash changes, so a live change to the current box still emits. `GET` reuses the latest read if it is under 1 second old. Otherwise it triggers its own read, whether or not anyone is subscribed. Size is not a concern on localhost: a Gen 3 read is about 33 KB and a full event roughly 0.4 MB (about 420 Pokémon at about 1 KB of JSON each), sent only to subscribers. A new subscriber gets the current value first, as in 006. The cadence (about every 2 seconds) and the scheduler belong to [Read loop](./018-read-loop.md). That ticket also owns an open dependency: mGBA's GDB stub caps reads at 512 bytes (per the adapter research in `../assets/001-emulator-memory-access.md`), so it must chunk the Gen 3 read or `boxes` is `unsupported` on that adapter.
- **Viewer.** A Boxes screen, which amends [Viewer design](./008-viewer-design.md) from four screens to five. It has a box selector and a grid in slot order (5×4 for Gen 1-2, 6×5 for Gen 3). Clicking a slot opens the existing Pokémon card, which shows `null` fields as `—`. An unreadable box shows a short note, and corrupt slots get a distinct marker. The screen subscribes to `boxes` only while it is open. There is no search or filtering in v2.0.
- **Tests.** Gen 3 decoding needs the substructure order table and the checksum routine. Fixture tests run both against real save bytes, as part of [Decoder test fixtures](./014-decoder-fixtures.md). The same ticket covers Gen 1-2 box decoding (including slot order and terminator handling), a CFRU box fixture, and stale-SRAM behavior. Unit tests cover profile address resolution for `PokemonStorage` (static and pointer entries), hash-triggered emission, the `features.boxes` flag, and 503 checks running before `:n` validation.

Boxes reuse the party schema and decoders, so overlay code and the viewer need no second Pokémon type. On-demand reads keep the large Gen 3 block off the normal tick, and the whole-resource topic keeps 006's rule of no diffs and no refetch notices.

Excluded: deferring boxes, Gen 3 only or current-box-only scope, a summary topic with refetch notices, a reduced box Pokémon schema, computed stats in v2.0, reading boxes every tick, an error event on the SSE stream, a `400` for a bad `:n`, silently dropping corrupt slots, and box search or filtering.

Amends [API v2 contract](./006-api-contract.md): `status.game.features`, the `not_found` error code, the `boxes` resource shape, and nullable `hp`, `maxHp`, `stats` and `status` on the shared Pokémon schema (also used by [Battle tracker data model](./012-battle-tracker-data-model.md)).

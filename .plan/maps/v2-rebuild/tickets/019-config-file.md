# Config file

## Question

Where does the config file live, what format is it, and which settings does it hold?

Settings so far come from [App form factor](./003-app-form-factor.md) (adapter pin, probing, bind address, port, browser auto-open) and [Viewer design](./008-viewer-design.md) (icon source, sprite URL), plus whatever [Read loop and latency budget](./018-read-loop.md) adds. Decide the location per OS, format, precedence of flags over file, whether the viewer writes the file, and where the user profiles folder lives.

Input from [Battle tracker data model](./012-battle-tracker-data-model.md): viewer display preferences such as "Show unrevealed opponent Pokémon" live in the browser's localStorage, with URL query overrides, and not in the config file.

Input from [Importable package for overlay developers](./015-importable-package.md): the package exports `DEFAULT_BASE_URL`, built from the default port and bind host this ticket settles, so pick them as named constants the package can import.

Input from [Release pipeline](./017-release-pipeline.md): add an update-check on/off setting (default on), a `--port` flag, `--no-browser`, and a data-folder override as a flag or env var that the release smoke test uses to point at a temp folder. The program must shut down cleanly with exit code 0 on SIGINT and SIGTERM, and on Ctrl+C on Windows.

Input from [Read loop and latency budget](./018-read-loop.md): add `pollHz` (integer 5-60, default 20, clamped with a logged warning when out of range). The other loop timings are internal constants and not settings. `--debug` also enables `GET /debug/metrics`.

## Answer

Settings live in one plain JSON file, `config.json`, checked by a Zod schema. The viewer edits it through a viewer-only `/settings` route that only this machine can write to. Command-line flags override the file for one run and are never saved. User profiles and manual picks live in the data folder, in their own files.

- **Format.** Plain JSON with a top-level `configVersion: 1` for future migrations and no `$schema` key. The Zod schema is the only definition of the file. The program rewrites the file from the viewer, so comments would be lost in any format, and JSON needs no extra dependency.
- **Location.** `%APPDATA%\pokemon-memory-reader\config.json` on Windows, `$XDG_CONFIG_HOME/pokemon-memory-reader/config.json` on Linux (falling back to `~/.config`), and `~/Library/Application Support/pokemon-memory-reader/config.json` on macOS. On Windows and macOS this is the data folder. On Linux it follows XDG, so config and data sit apart. The Settings screen shows the path read-only.
- **Data-folder override.** `--data-dir <path>` or the `PMR_DATA_DIR` env var, with the flag winning, moves everything the program reads or writes into one root: `config.json`, `bridges/`, `profiles/` and `manual-picks.json`, on every OS. The release smoke test uses it, and it is how two instances get separate settings. The program creates the folder if it is missing, and exits 1 with a clear message if it can't write there. There is no separate `--config` flag.
- **Flags.** `--port <n>`, `--host <addr>`, `--no-browser`, `--data-dir <path>`, `--debug`, `--version` and `--help`. `PMR_DATA_DIR` is the only program-specific env var, besides the `XDG_*` variables the default Linux paths follow. Precedence is flag > file > built-in default, and for the data folder only, flag > env > default. Flag values apply to the current run and are never written to the file. An unknown flag or an invalid value, such as `--port abc` or a port outside 1-65535, prints usage to stderr and exits 2. `--help` and `--version` exit 0.
- **Default port and host.** Port `7425` and host `127.0.0.1`. The API package's `/client` subpath exports `DEFAULT_PORT`, `DEFAULT_HOST` and `DEFAULT_BASE_URL` (`http://127.0.0.1:7425`), and the config schema takes its defaults from them. `localhost` is avoided because some systems resolve it to `::1` first while the server binds IPv4. Overlay docs use `http://127.0.0.1:7425`. Before `2.0.0-rc.1`, `RELEASING.md` checks that 7425 is not IANA-assigned. If it is, the implementer picks the nearest unassigned port in 7400-7499 and updates this ticket. The default is frozen from `2.0.0-rc.1` through all of 2.x. Changing `port` in Settings is allowed, and the viewer warns that overlays using `DEFAULT_BASE_URL` will need the new URL.
- **Settings.** The full `config.json`, with defaults. The two bridge ports are set by [Bridge wire protocol](./022-bridge-wire-protocol.md) and the `icons` shape by [Icon loading and fallbacks](./021-icon-loading.md); until those resolve, the placeholders below are open dependencies, not values:

  ```json
  {
    "configVersion": 1,
    "port": 7425,
    "host": "127.0.0.1",
    "openBrowser": true,
    "adapter": "auto",
    "adapters": {
      "mgba":      { "host": "127.0.0.1", "port": "<set by Bridge wire protocol>" },
      "retroarch": { "host": "127.0.0.1", "port": 55355 },
      "bizhawk":   { "host": "127.0.0.1", "port": "<set by Bridge wire protocol>" }
    },
    "pollHz": 20,
    "updateCheck": true,
    "icons": "<shape set by Icon loading and fallbacks>"
  }
  ```

  `adapter` is exactly one of `"auto"`, `"mgba"`, `"retroarch"` or `"bizhawk"`, and a pinned adapter turns probing off. There is no value that disables every adapter. `adapters` holds each adapter's endpoint, so the emulator can run on another machine, and probing uses these endpoints. Ports are integers 1-65535 and hosts are non-empty strings. `pollHz` follows the read loop rule: an out-of-range integer is clamped to 5-60 with a warning, and a non-integer or non-number falls back to 20 with a warning. The schema has no cross-field port checks. A port clash shows up as a failed connection or a port-in-use error, and both errors name the host and port involved. There is no log-level setting (`--debug` only) and no profiles-folder setting.
- **What is a setting.** A viewer choice belongs in `config.json` only when it must match across the OBS browser source and the user's normal browser, because each has its own localStorage. Icon source qualifies. This is the one stated exception to the rule that viewer display preferences stay out of the config file. Everything else, such as "Show unrevealed opponent Pokémon", stays in localStorage with URL overrides, per [Battle tracker data model](./012-battle-tracker-data-model.md).
- **Viewer writes.** `GET /settings` and `PUT /settings` sit outside `/api/v2`, carry no stability promise and are not in the API package. `GET` returns each setting's value plus its `source` (`"flag"`, `"file"` or `"default"`) and `restartRequired`, so the viewer hardcodes neither. Values are the ones the running instance applied. When the file holds a different value that waits for a restart, `GET` also returns it as `pending`, so the viewer never shows an unapplied edit as active. `PUT` takes a partial patch of known keys, checked by the same schema. It can never change `configVersion` or the data folder. The file is created on the first save, and a missing file means defaults. Each save re-reads the file from disk, applies the patch, keeps unknown keys, and writes a temp file with a per-process unique name in the same folder, then renames it over the original. Two instances sharing one data folder therefore never clobber each other's unrelated keys, and the last writer wins on the same key. The rare lost update when two saves overlap is accepted, with no lock file.
- **Write protection.** The API stays without auth, but writes are guarded. `PUT /settings` is accepted only when the socket's peer address is loopback (never `X-Forwarded-For`), the `Content-Type` is `application/json` (which forces a CORS preflight the route never approves), the `Host` header is `localhost`, `127.0.0.1`, `[::1]` or the configured bind host with the port, and any `Origin` header present equals the server's own origin. LAN clients can read `/settings` but not write it. No token. `/api/v2` and the API package stay read-only, as the map's notes say. `/settings` is a viewer-only write route and the one deliberate exception to the no-auth stance, which is why it carries these guards. Each rejection path has a test. This closes CSRF and DNS-rebinding attacks from web pages and stops LAN clients from flipping the bind address or pointing adapters at other hosts.
- **When changes apply.** Adapter pin and endpoints, `pollHz`, `updateCheck` and icon settings apply live. `port`, `host` and `openBrowser` are read only at startup, and the viewer says "restart to apply". A field a flag overrides shows as overridden and disabled. Hand edits to the file are read only at startup. Nothing watches the file, so an instance keeps its in-memory settings until it restarts.
- **Bad or missing file.** The program always stays running, so a typo never kills a streamer's overlay. A missing file means defaults, and nothing is written. Malformed JSON logs an error naming the path, runs on defaults, and refuses saves. A key with an invalid value falls back to its default with one warning. Unknown keys warn once and survive saves. A `configVersion` newer than the program knows runs on the keys it understands and refuses saves. A refused save returns an error code from `PUT /settings`, and the viewer shows a banner naming the path while still displaying the current values read-only.
- **User profiles.** `<data folder>/profiles/`, fixed and moved only by the data-folder override. The program creates the empty folder at startup so the viewer can show its path.
- **Manual picks.** `<data folder>/manual-picks.json`, a program-owned state file kept apart from settings. It is keyed `sha1:<hex>` when the hash is known, else `header:<gameCode>:<revision>:<title>`. It is checked by Zod and saved with the same re-read, merge and atomic-rename rule. A malformed file is renamed to `manual-picks.json.bad` and replaced with empty state, since nobody writes it by hand. The `.bad` copy keeps the old picks for recovery. `config.json` gets the opposite treatment because a person edits it, and overwriting a typo would lose their work.
- **Contract package.** A private workspace package `internal/` (`@pokemon-memory-reader/internal`, `"private": true`, never published) holds the config file schema and the `/settings` route contract as Zod schemas with inferred types and pure helpers only. `server/` and `viewer/` import it. It imports `api/` only for `DEFAULT_PORT` and `DEFAULT_HOST`. A check fails if `api/` imports `internal/` or `server/`, or if `viewer/` imports `server/`.
- **Console output.** At startup the program prints the version line, the data folder path, the config file path (with "not created yet, using defaults" when it's missing), then the viewer URL. When `host` is not loopback, whether set by the file or by `--host`, it prints a LAN warning: the API and viewer are reachable by anyone on the network, and settings stay writable only from this machine. With `0.0.0.0` it prints one URL per non-internal IPv4 interface, and with a specific address only that one. `--debug` adds detail.
- **Startup failures.** A port already in use prints an error naming the port and suggesting `--port`, which notes that a second emulator needs its own port, then exits 1. The program never falls back to another port silently, since overlays rely on `DEFAULT_BASE_URL`. On Windows only, after a fatal startup error, when stdin and stdout are both TTYs, the program prints "Press Enter to close" and waits, so a double-clicked console doesn't vanish. It then exits with the same code. With no TTY, as in the smoke test and scripts, it exits at once. A server test checks that a port conflict exits 1 with no TTY and does not wait.
- **Shutdown.** SIGINT, SIGTERM and Ctrl+C on Windows stop the loop, close SSE streams and the adapter, and exit 0 within 2 s. A second signal in that window exits at once with 130. If graceful shutdown takes longer than 2 s, the program logs the step that hung and exits 1. The 130 and 1 codes are deliberate exceptions to exit 0, and both are for abnormal shutdowns. The smoke test asserts exit 0 on a single signal only, and server tests cover the other two paths.
- **Debug metrics.** `GET /debug/metrics` exists only under `--debug`, sits outside `/api/v2`, is read-only, answers loopback peers only, is not in the API package, and carries no stability promise. The route, its `--debug` gate and its place outside `/api/v2` come from [Read loop and latency budget](./018-read-loop.md). Loopback-only and read-only are this ticket's decisions.
- **Update check.** Unchanged from [Release pipeline](./017-release-pipeline.md), plus two rules. It runs asynchronously after the server is listening and never delays startup. Turning `updateCheck` off live cancels the next check, and turning it back on schedules one shortly after. A failed check logs only under `--debug`.

The design keeps setup to zero for streamers (no file until they save one, a default URL overlays can hardcode) and gives the smoke test and two-emulator setups one override.

Excluded: JSONC, TOML and YAML; config next to the executable; a `--config` flag; an env var per setting; writing flag values to the file; a read-only Settings screen; settings in localStorage; a console token for writes; LAN writes; hot-reloading the file; rebinding live; falling back to a free port; port 8080; `localhost` as the default host; a lock file between instances; a configurable profiles folder; manual picks inside `config.json`; refusing to start on a bad file; the settings contract in `server/` with a type-only exception for the viewer; Explorer detection through native FFI; and a log-level setting.

Amends [Importable package for overlay developers](./015-importable-package.md): the config file schema moves into `internal/`, not `server/`, and the `/client` subpath of `api/` exports `DEFAULT_PORT` and `DEFAULT_HOST` beside `DEFAULT_BASE_URL`. Amends [Viewer design](./008-viewer-design.md): Settings shows each field's source, flag overrides and "restart to apply", the config and profiles paths, and a banner when saves are refused. Adds input to [Bridge wire protocol](./022-bridge-wire-protocol.md) and [Icon loading and fallbacks](./021-icon-loading.md).
